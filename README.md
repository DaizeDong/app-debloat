## Design Philosophy

Adware-ish desktop apps (input methods, cloud drives, downloaders, translators, office suites, OEM utilities) rarely give you a real off switch. Their ads, AI add-ons and telemetry are separate components started by a launcher, gated by a config the settings page does not control, and brought back by an updater, a repair service or a remote-config SDK. Deleting files or flipping UI toggles fails for the same reason every time: it treats the symptom, not the gate and not the way back.

This skill turns the method that worked on Sogou Pinyin into a repeatable pipeline: inventory everything the app put on the machine, map who launches each component and what decides whether it runs, list every re-install path, block those with the least invasive lever, prove the result by behavior (processes, modules, connections, a core-function probe, a reboot, a triggered repair), and keep it applied after updates. The generic steps only find candidates; each app must answer a fixed list of app-specific questions before anything is changed, because no two apps hide their gates in the same place.

## Purpose and Scope

For one installed third-party Windows desktop app at a time. Inputs: the app name, what must keep working, and what should go. Outputs: an evidence ledger, a plan, and a single-file PowerShell script with dry-run, `-Apply`, `-Install` (re-apply at logon and every 6 hours) and `-Uninstall`.

Not covered: Windows-wide debloat, malware removal, uninstalling, browser ad blocking, cracking or license bypass, binary patching, recommending other software. Tencent-family clients are limited to out-of-process measures.

```powershell

.\skills\app-debloat\scripts\setup_re_backend.ps1 -Install        # REA + Ghidra 12.1.4 + JDK 21 into %LOCALAPPDATA%
```

## Quick Start

Ask Claude Code in plain words, for example: "Youdao Translate keeps popping up ads and an AI assistant, find what launches them and block it without breaking translation." The skill then:

1. Snapshots the app read-only (`inventory.ps1`) and picks a reverse-engineering backend.
2. Maps the launch chain and gates (`pe_triage.py`, REA/Ghidra, frida), and the re-install paths.
3. Writes `analysis.md` and `plan.md` and asks before any change.
4. Builds `<App>Debloat.ps1` from a manifest and runs it in dry-run, then `-Apply` and `-Install` once you approve.
5. Verifies after apply, after a reboot and after a triggered repair.

## How to Invoke

Phrases such as "this app is full of ads, slim it down", "it keeps coming back after every update", "find its self-repair mechanism", "disable its telemetry and AI assistant but keep it usable", "debloat <app name>".

## Example Output

`examples/` holds two synthetic apps generated by `tools/make_fixtures.py`: a manifest, optional hooks and the built single-file script for each. A real worked case is the public [sogou-ime-debloat](https://github.com/SanJerry007/sogou-ime-debloat) repo; its method is summarized in `skills/app-debloat/reference/case-sogou.md`.

## Limitations

- Static analysis offsets are valid for one build only; every app upgrade needs the inventory and the gate questions re-checked (the installed task warns when the version fingerprint changes).
- Code that runs inside another process (an IME, a shell extension) cannot be firewalled per program.
- Server-pushed switches can change behavior without any file change; verification is by behavior, not file state.
- Antivirus may flag or silently revert IFEO and hosts changes; the pipeline re-reads them, but cannot prevent it.
- Account-bound apps can kick or ban modified clients; in-tree changes need the owner's explicit consent per app.
- Real analyses stay private: ledgers, snapshots and verification records belong in a private companion repo, never in a public one.
